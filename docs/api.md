# Спецификация REST API веб-приложения

Документ содержит описание ключевых эндпоинтов подсистем `tickets` (учет заявок) и `instruments` (учет оборудования).  
Все ответы и тела запросов передаются в формате `application/json`. Для всех изменяющих методов (`POST`, `PUT`, `PATCH`, `DELETE`) при аутентификации через сессии браузера обязательна передача заголовка `X-CSRFToken` со значением из cookie `csrftoken`.

---

## 1. Подсистема заявок (Tickets API)

### Карточка 1: Получение реестра заявок
| Параметр | Описание |
| :--- | :--- |
| **Метод и адрес** | `GET /api/tickets/` |
| **Назначение** | Получение списка всех зарегистрированных заявок текущего пользователя или подразделения с возможностью фильтрации |
| **Аутентификация** | Требуется сессия пользователя (`sessionid`) |
| **Тело запроса** | Отсутствует (параметры передаются через query string, например: `?status=new`) |
| **Успех** | `HTTP 200 OK`, JSON-массив объектов заявок:<br>`[{"id": 1, "title": "Сбой сети", "description": "Нет линка", "status": "new", "created_at": "2026-11-04T10:00:00Z"}]` |
| **Ошибки** | `401 Unauthorized` — пользователь не авторизован |
| **Проверка** | В панели Network браузера отображается статус 200, в ответе получен валидный JSON-массив |

---

### Карточка 2: Создание новой заявки
| Параметр | Описание |
| :--- | :--- |
| **Метод и адрес** | `POST /api/tickets/` |
| **Назначение** | Регистрация нового обращения/инцидента в системе |
| **Аутентификация** | Требуется сессия пользователя и заголовок `X-CSRFToken` |
| **Тело запроса** | `{"title": "Замена кабеля", "description": "Поврежден разъем RJ-45 на рабочем месте"}` |
| **Успех** | `HTTP 201 Created`, JSON созданной заявки:<br>`{"id": 14, "title": "Замена кабеля", "description": "Поврежден разъем RJ-45 на рабочем месте", "status": "new", "created_at": "2026-11-04T12:30:00Z", "updated_at": "2026-11-04T12:30:00Z"}` |
| **Ошибки** | `400 Bad Request` — не переданы обязательные поля (`title`, `description`);<br>`403 Forbidden` — отсутствует валидный CSRF-токен |
| **Проверка** | В Network зафиксирован POST-запрос с кодом 201, новая карточка тикета сразу отрисовывается в DOM через `app.js` |

---

### Карточка 3: Изменение статуса заявки
| Параметр | Описание |
| :--- | :--- |
| **Метод и адрес** | `PATCH /api/tickets/<id>/` |
| **Назначение** | Изменение статуса обработки заявки (перевод в работу или закрытие) |
| **Аутентификация** | Требуется сессия пользователя и заголовок `X-CSRFToken` |
| **Тело запроса** | `{"status": "in_progress"}` |
| **Успех** | `HTTP 200 OK`, JSON обновленной заявки:<br>`{"id": 14, "title": "Замена кабеля", "description": "Поврежден разъем RJ-45", "status": "in_progress", "updated_at": "2026-11-04T12:45:00Z"}` |
| **Ошибки** | `400 Bad Request` — передано недопустимое значение статуса;<br>`404 Not Found` — заявка с указанным идентификатором отсутствует |
| **Проверка** | В Network виден PATCH со статусом 200, изменение статуса отображается в UI без перезагрузки страницы и подтверждается при чтении из БД |

## 2. Подсистема учета оборудования (Instruments API)

### Карточка 4: Каталог доступного инвентаря
| Параметр | Описание |
| :--- | :--- |
| **Метод и адрес** | `GET /api/instruments/` |
| **Назначение** | Получение перечня инструментов и оборудования с их инвентарными номерами и признаком доступности |
| **Аутентификация** | Требуется сессия пользователя |
| **Тело запроса** | Отсутствует |
| **Успех** | `HTTP 200 OK`, JSON-список инструментов:<br>`[{"id": 3, "name": "Осциллограф цифровой", "inventory_number": "INV-00492", "status": "available", "description": "Двухканальный, 100 МГц"}]` |
| **Ошибки** | `401 Unauthorized` — неавторизованный доступ |
| **Проверка** | GET-запрос возвращает массив с актуальными инвентарными единицами |

---

### Карточка 5: Формирование запроса на получение оборудования
| Параметр | Описание |
| :--- | :--- |
| **Метод и адрес** | `POST /api/instruments/requests/` |
| **Назначение** | Создание заявки сотрудника на выдачу конкретной единицы оборудования |
| **Аутентификация** | Требуется сессия пользователя и заголовок `X-CSRFToken` |
| **Тело запроса** | `{"instrument": 3}` |
| **Успех** | `HTTP 201 Created`, JSON созданного запроса:<br>`{"id": 8, "instrument": 3, "user": 2, "status": "pending", "created_at": "2026-11-04T13:00:00Z"}` |
| **Ошибки** | `400 Bad Request` — инструмент в данный момент недоступен для выдачи (находится на обслуживании или уже выдан);<br>`404 Not Found` — инструмент с указанным `id` не существует |
| **Проверка** | В Network фиксируется статус 201, в таблице `instruments_instrumentrequestevent` создается запись аудита со снимком наименования |

---

### Карточка 6: Смена статуса запроса оборудования / фиксация возврата
| Параметр | Описание |
| :--- | :--- |
| **Метод и адрес** | `PATCH /api/instruments/requests/<id>/` |
| **Назначение** | Утверждение, отклонение заявки диспетчером или фиксация возврата инвентаря на склад |
| **Аутентификация** | Требуется сессия пользователя с правами диспетчера/персонала и заголовок `X-CSRFToken` |
| **Тело запроса** | `{"status": "returned"}` |
| **Успех** | `HTTP 200 OK`, обновленный объект запроса:<br>`{"id": 8, "instrument": 3, "status": "returned", "created_at": "2026-11-04T13:00:00Z"}` |
| **Ошибки** | `400 Bad Request` — недопустимый переход жизненного цикла;<br>`403 Forbidden` — недостаточно прав (пользователь не является администратором/диспетчером) |
| **Проверка** | В Network получен статус 200, статус инвентаря в связанной таблице `instruments_instrument` автоматически переводится в `available` |
