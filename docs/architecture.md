# Архитектурная схема программного решения

В данном документе приведено описание многоуровневой архитектуры веб-приложения учета заявок и инвентаря, границ между подсистемами и путей передачи данных.

## 2. Границы взаимодействия и зоны ответственности

1. **Клиентская граница (Браузер)**:
   - Отвечает за представление данных и взаимодействие с пользователем.
   - Отправка запросов разделена на два типа:
     - Синхронная навигация: переход по страницам, отправка форм входа и регистрации с перезагрузкой.
     - Асинхронная коммуникация: функции JavaScript (`tickets/static/tickets/app.js`) перехватывают действия пользователя (клик по смене статуса, подтверждение выдачи) и отправляют `fetch`-запросы в формате JSON без перезагрузки интерфейса.
   - Клиент обязан передавать значение из cookie `csrftoken` в HTTP-заголовке `X-CSRFToken` при отправке изменяющих запросов (POST, PUT, PATCH, DELETE).

2. **Граница отдачи статических файлов (WhiteNoise)**:
   - В облачной конфигурации статические файлы (CSS-фреймворк Tabler, шрифты, JS) отдаются непосредственно WSGI-сервером через библиотеку `WhiteNoise`.
   - Запросы к `/static/*` обрабатываются до передачи управления бизнес-логике Django, снижая накладные расходы на сервер.

3. **Граница серверных приложений (Django & DRF)**:
   - `config/urls.py` разделяет потоки: классические запросы рендерят HTML-страницы через движок шаблонов (`tickets/templates/`), а API-маршруты делегируются DRF-сериализаторам.
   - DRF изолирует формат данных, проверяет права доступа (`permissions`) и валидирует типы полей перед сохранением.

4. **Граница доступа к данным (Django ORM & СУБД)**:
   - Ни один модуль не формирует ручные строковые SQL-запросы; все операции проходят через ORM.
   - Слой абстракции базы данных динамически переключает движок в зависимости от переменной `DATABASE_URL`, обеспечивая идентичность логики на локальной SQLite и на облачной PostgreSQL.


## Структура проекта

```
SRS7-SRS8-BD/
│
├── config/                     # Главный конфигурационный пакет Django-проекта
│   ├── __init__.py             # Инициализация пакета
│   ├── asgi.py                 # Точка входа для асинхронных серверов (ASGI)
│   ├── wsgi.py                 # Точка входа для WSGI-сервера (Gunicorn/Render)
│   ├── urls.py                 # Главный диспетчер маршрутов (подключение tickets, instruments, admin)
│   └── settings.py             # Центральный файл настроек (БД, middleware, статика, auth)
│
├── tickets/                    # Приложение: система заявок и обращений
│   ├── migrations/             # Миграции схемы данных заявок
│   ├── static/tickets/         # Клиентские скрипты (app.js — AJAX/fetch логика)
│   ├── templates/              # HTML-шаблоны страниц (base.html, dashboard.html, registration/)
│   ├── admin.py                # Конфигурация отображения заявок в панели Django Admin
│   ├── apps.py                 # Конфигурация приложения tickets
│   ├── forms.py                # Django-формы (регистрация, создание тикетов)
│   ├── models.py               # Модели данных (сущность Ticket и категории)
│   ├── serializers.py          # Сериализаторы DRF для преобразования моделей в JSON
│   ├── urls.py                 # Маршруты UI-представлений и REST API тикетов
│   └── views.py                # Контроллеры UI и DRF APIView / ViewSets
│
├── instruments/                # Приложение: учет оборудования и инвентаря
│   ├── migrations/             # Миграции схемы данных оборудования
│   ├── admin.py                # Регистрация сущностей оборудования в панели администратора
│   ├── apps.py                 # Конфигурация приложения instruments
│   ├── models.py               # Модели: Instrument, InstrumentRequest, InstrumentRequestEvent
│   ├── serializers.py          # Сериализаторы DRF для инвентаря и запросов
│   ├── urls.py                 # Маршруты REST API и представлений инвентаря
│   └── views.py                # Контроллеры обработки бронирования и истории аудита
│
├── docs/                       # Техническая документация (требование СРС №8)
│   ├── architecture.md         # Архитектурная схема и взаимодействие компонентов
│   ├── database.md             # Схема БД, поля сущностей и связи
│   ├── api.md                  # Спецификация маршрутов REST API
│   ├── deployment.md           # Инструкция по развертыванию на Render (Postgres + Web Service)
│   └── troubleshooting.md      # Диагностика и устранение 5+ типовых проблем
│
├── build.sh                    # Скрипт сборки на Render (pip install, collectstatic, migrate)
├── manage.py                   # Служебная консольная утилита управления Django
├── requirements.txt            # Список внешних зависимостей проекта
├── .env.example                # Шаблон безопасных переменных окружения
├── .gitignore                  # Список файлов, исключенных из Git (venv, db.sqlite3, .env)
└── README.md                   # Главный документ: описание, быстрый старт, ссылки
